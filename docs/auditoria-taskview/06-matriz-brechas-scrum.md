# 06 — Matriz de brechas Scrum

Clasificación del **código local**, no certificación de funciones en las imágenes instaladas. EXISTENTE = implementación reutilizable; PARCIAL = base con ampliación requerida; NO EXISTENTE = no se encontró implementación en el alcance buscado; NO VERIFICADA = evidencia insuficiente. Esfuerzo relativo de adaptación al piloto de dos programadores, sin compromiso de plazos: bajo = configuración/ajuste acotado; medio = varios componentes/contratos; alto = cambios transversales de datos, seguridad o sincronización.

## Scrum frente a opciones de producto

Product Backlog/Product Goal, Sprint Backlog/Sprint Goal e Increment/Definition of Done son artefactos y compromisos del marco. Épicas, historias, puntos, gráficos, GitLab y columnas de QA son decisiones de producto; no son requisitos universales Scrum. Review inspecciona resultados con interesados; retrospectiva mejora la forma de trabajo. La guía define sprints de un mes o menos; el código permite cadencias hasta 90 días y pausas, por lo que se necesita una política de uso, no afirmar conformidad automática. Fuente: [Scrum Guide oficial](https://scrumguides.org/scrum-guide.html).

Para SGAF–Cobranzas, priorizar jerarquía y criterios, luego QA y métricas, conservando sprints/retro/roles ya implementados. No comenzar funciones GitLab avanzadas antes de tener IDs, permisos y contratos estables.
